# Как выпустить релиз

Автообновление LAZEYKA читает **последний релиз** репозитория
`reb0oornalexey/LAZEYKA` и сверяет его версию с установленной. Контракт
зашит в `src/main/core/app-updater.ts` — если релиз ему не соответствует,
приложение просто не увидит обновление, без единой ошибки на экране.

## Что именно проверяет приложение

| Требование | Где в коде | Что будет при нарушении |
| --- | --- | --- |
| Репозиторий `reb0oornalexey/LAZEYKA` | `const REPO` | обновления берутся не оттуда |
| Релиз **не** draft и **не** pre-release | `release.draft \|\| release.prerelease` | `hasUpdate: false`, плашка не появится |
| Тег содержит версию: `v1.0.2` или `1.0.2` | `parseVersion(tag_name)` | версия не распознана, сравнение не состоится |
| Версия тега **больше** установленной | `compareVersion(latest, installed) > 0` | обновления нет |
| Ассет с именем `LAZEYKA_x64.exe` | `/^LAZEYKA_x64\.exe$/i` | плашка появится, но кнопка «Обновить» не сработает |

Запасной вариант имени ассета — любой `LAZEYKA*.exe` без слова `portable`.
Но `electron-builder.yml` и так называет установщик `LAZEYKA_x64.exe`, так
что ничего переименовывать не нужно.

Ответ GitHub кэшируется на 30 минут, и кэш лежит файлом в
`%APPDATA%\lazeyka\update-cache-app.json` — он переживает перезапуск. Чтобы не
ждать, нажмите «Проверить обновления сейчас» в настройках: эта кнопка идёт в
сеть мимо кэша и показывает ошибку, если проверка не удалась.

Раньше кэш держался шесть часов, и после публикации релиза приложение молчало
полдня, а перезапуск не помогал — с экрана «обновлений нет» было не отличить
от «мы не спрашивали».

## Сборка

Собирать нужно **на Windows**: установщик делается через NSIS, а
`node_modules` содержит Windows-сборку Electron. На Linux/macOS сборка
Windows-инсталлятора не пройдёт.

```powershell
# из консоли с правами администратора
pnpm install
pnpm typecheck        # обе конфигурации должны пройти без ошибок
pnpm build:win
```

На выходе в `dist\`:

| Файл | Куда |
| --- | --- |
| `LAZEYKA_x64.exe` | **в релиз** — это то, что качает автообновление |
| `LAZEYKA_x64.exe.blockmap` | можно приложить, не обязателен |
| `LAZEYKA_x64-portable.7z` | по желанию, портативная версия |
| `win-unpacked\` | не выкладывать |

## Публикация

1. Поднимите версию в `package.json` (приложение берёт её через
   `app.getVersion()`, больше нигде её дублировать не нужно).
2. Соберите и проверьте, что установщик запускается.
3. Создайте релиз с тегом `v<версия>` — например `v1.0.2`.
4. Приложите `LAZEYKA_x64.exe` как ассет.
5. Снимите галочки «Set as a pre-release» и «Save as draft» — иначе
   приложение этот релиз проигнорирует.

## Как проверить, что автообновление работает

1. Установите сборку с версией **ниже** релизной (например 1.0.1).
2. Выложите релиз `v1.0.2` по инструкции выше.
3. Запустите установленную 1.0.1 → должна появиться плашка обновления.
   Если нет — откройте вкладку «Логи», там будет причина.
4. Нажмите «Обновить». Приложение скачает установщик в `%TEMP%`, запишет
   маркер `.lazeyka-upgrade` рядом с `LAZEYKA.exe` (по нему **старый**
   деинсталлятор понимает, что это апгрейд, и не сносит `%APPDATA%\lazeyka`
   с вашими настройками), запустит установщик тихо и перезапустит себя.

Логи перезапуска пишутся в `%TEMP%\LAZEYKA-relaunch-*.log` — туда стоит
заглянуть, если после обновления приложение не поднялось само.

## macOS

Сборка под Mac делается **в CI**, вручную на Mac собирать не нужно.
Workflow `.github/workflows/build-mac.yml` запускается при пуше тега `v*`
(и вручную через «Run workflow»), собирает две сборки параллельно и кладёт
образы в релиз этого тега:

| Ассет | Для чего |
| --- | --- |
| `LAZEYKA_arm64.dmg` | Apple Silicon (M1 и новее) |
| `LAZEYKA_x64.dmg` | Intel |

Порядок для владельца не меняется: релиз по-прежнему создаётся вручную с
Windows (раздел «Публикация»). Если тег запушен раньше, чем создан релиз,
job `Загрузка .dmg в релиз` ждёт его до ~10 минут; если релиз так и не
появился — создайте его и перезапустите упавший job. Приложение ищет на Mac
ассет `LAZEYKA_<arm64|x64>.dmg`; пока его в релизе нет, обновления для Mac
не предлагается. Автоустановки на Mac нет: кнопка «Скачать» открывает `.dmg`
в браузере, дальше LAZEYKA перетаскивается в «Программы» поверх старой версии.

Ядра INCY (sing-box, Xray) на Mac скачивает `scripts/fetch-mac-binaries.mjs`
в папку `resources-mac/` (она в `.gitignore`); версии зафиксированы
константами в начале скрипта — держите их равными версиям ядер Windows-сборки.
Локально: `pnpm fetch:mac arm64` (или `x64`) перед `electron-builder --mac`.

### Подпись и первый запуск

Сертификата Apple Developer нет, поэтому приложение подписано **ad-hoc**
(`identity: '-'`): без такой подписи arm64-сборка не запустится вообще, но
Gatekeeper всё равно считает разработчика неизвестным. Первый запуск:

1. Перетащите LAZEYKA из `.dmg` в «Программы» и запустите. macOS покажет, что
   приложение не может быть проверено.
2. «Системные настройки → Конфиденциальность и безопасность» → прокрутите
   вниз до сообщения о LAZEYKA → **«Всё равно открыть»** (Open Anyway) →
   подтвердите паролем. На macOS Sequoia и новее старый способ «правая кнопка →
   Открыть» больше не работает.
3. Альтернатива из терминала — снять карантин:
   `xattr -dr com.apple.quarantine /Applications/LAZEYKA.app`

Hardened runtime и нотаризация выключены (без платного аккаунта разработчика
они невозможны), поэтому файл `build/entitlements.mac.plist` сборкой не
используется.
