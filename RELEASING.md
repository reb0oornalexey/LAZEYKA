# Как выпустить релиз

Автообновление LAZEYKA читает **последний релиз** репозитория
`reb0oornalexey/LAZEYKA` и сверяет его версию с установленной. Контракт
зашит в `src/main/core/app-updater.ts` — если релиз ему не соответствует,
приложение просто не увидит обновление, без единой ошибки на экране.

## Что именно проверяет приложение

| Требование | Где в коде | Что будет при нарушении |
| --- | --- | --- |
| Репозиторий `reb0oornalexey/LAZEYKA` | `const REPO` | обновления берутся не оттуда |
| Релиз **не** draft и **не** pre-release | `release.draft \|\| release.prerelease` | `hasUpdate: false`, плашка не появится |
| Тег содержит версию: `v1.0.2` или `1.0.2` | `parseVersion(tag_name)` | версия не распознана, сравнение не состоится |
| Версия тега **больше** установленной | `compareVersion(latest, installed) > 0` | обновления нет |
| Ассет с именем `LAZEYKA_x64.exe` | `/^LAZEYKA_x64\.exe$/i` | плашка появится, но кнопка «Обновить» не сработает |

Запасной вариант имени ассета — любой `LAZEYKA*.exe` без слова `portable`.
Но `electron-builder.yml` и так называет установщик `LAZEYKA_x64.exe`, так
что ничего переименовывать не нужно.

Ответ GitHub кэшируется на 30 минут, и кэш лежит файлом в
`%APPDATA%\lazeyka\update-cache-app.json` — он переживает перезапуск. Чтобы не
ждать, нажмите «Проверить обновления сейчас» в настройках: эта кнопка идёт в
сеть мимо кэша и показывает ошибку, если проверка не удалась.

Раньше кэш держался шесть часов, и после публикации релиза приложение молчало
полдня, а перезапуск не помогал — с экрана «обновлений нет» было не отличить
от «мы не спрашивали».

## Сборка

Собирать нужно **на Windows**: установщик делается через NSIS, а
`node_modules` содержит Windows-сборку Electron. На Linux/macOS сборка
Windows-инсталлятора не пройдёт.

```powershell
# из консоли с правами администратора
pnpm install
pnpm typecheck        # обе конфигурации должны пройти без ошибок
pnpm build:win
```

На выходе в `dist\`:

| Файл | Куда |
| --- | --- |
| `LAZEYKA_x64.exe` | **в релиз** — это то, что качает автообновление |
| `LAZEYKA_x64.exe.blockmap` | можно приложить, не обязателен |
| `LAZEYKA_x64-portable.7z` | по желанию, портативная версия |
| `win-unpacked\` | не выкладывать |

## Публикация

1. Обновите версию в `package.json` и описание в [CHANGELOG.md](./CHANGELOG.md).
2. Соберите Windows. Команда `node scripts\release-notes.mjs` подготовит
   `release-notes-v<версия>.md` с SHA-256 файлов в `dist`. Если пакет Ubuntu
   уже готов, его можно передать вторым аргументом после папки сборки Windows.
3. Приложите `LAZEYKA_x64.exe`, портативный архив, `.blockmap` и готовый
   `LAZEYKA_amd64.deb`, если он есть. Передайте заметки через
   `gh release create --notes-file`. Этот текст использует окно «Что нового».
4. Опубликуйте стабильный релиз с тегом `v<версия>`. После публикации
   `build-mac` добавит DMG для Apple Silicon и Intel, а `build-linux`
   соберёт и добавит пакет Ubuntu, если его ещё нет среди файлов релиза.

## Как проверить, что автообновление работает

1. Установите сборку с версией **ниже** релизной (например 1.0.1).
2. Выложите релиз `v1.0.2` по инструкции выше.
3. Запустите установленную 1.0.1 → должна появиться плашка обновления.
   Если нет — откройте вкладку «Логи», там будет причина.
4. Нажмите «Обновить». Приложение скачает установщик в `%TEMP%`, запишет
   маркер `.lazeyka-upgrade` рядом с `LAZEYKA.exe` (по нему **старый**
   деинсталлятор понимает, что это апгрейд, и не сносит `%APPDATA%\lazeyka`
   с вашими настройками), запустит установщик тихо и перезапустит себя.

Логи перезапуска пишутся в `%TEMP%\LAZEYKA-relaunch-*.log` — туда стоит
заглянуть, если после обновления приложение не поднялось само.

## macOS

Сборка под Mac делается **в CI**, вручную на Mac собирать не нужно.
Workflow `.github/workflows/build-mac.yml` запускается сам, как только релиз
опубликован (`gh release create …`), собирает две сборки параллельно и
докладывает образы в этот релиз (через 10–15 минут после публикации).
Ручной запуск («Run workflow») только собирает и кладёт файлы в артефакты:

| Ассет | Для чего |
| --- | --- |
| `LAZEYKA_arm64.dmg` | Apple Silicon (M1 и новее) |
| `LAZEYKA_x64.dmg` | Intel |

Порядок для владельца не меняется: релиз по-прежнему создаётся вручную с
Windows (раздел «Публикация»), ничего дополнительно запускать не нужно.
Если job упал — Actions → build-mac → Re-run failed jobs. Приложение ищет на Mac
ассет `LAZEYKA_<arm64|x64>.dmg`; пока его в релизе нет, обновления для Mac
не предлагается. Автоустановки на Mac нет: кнопка «Скачать» открывает `.dmg`
в браузере, дальше LAZEYKA перетаскивается в «Программы» поверх старой версии.

Ядра INCY (sing-box, Xray) на Mac скачивает `scripts/fetch-mac-binaries.mjs`
в папку `resources-mac/` (она в `.gitignore`); версии зафиксированы
константами в начале скрипта. sing-box берётся из того же форка, что и на
Windows (`Leadaxe/sing-box-lx`, с AmneziaWG), — официальный SagerNet не подходит.
Локально: `pnpm fetch:mac arm64` (или `x64`) перед `electron-builder --mac`.

### Подпись и первый запуск

Сертификата Apple Developer нет, поэтому приложение подписано **ad-hoc**
(`identity: '-'`): без такой подписи arm64-сборка не запустится вообще, но
Gatekeeper всё равно считает разработчика неизвестным. Первый запуск:

1. Перетащите LAZEYKA из `.dmg` в «Программы» и запустите. macOS покажет, что
   приложение не может быть проверено.
2. «Системные настройки → Конфиденциальность и безопасность» → прокрутите
   вниз до сообщения о LAZEYKA → **«Всё равно открыть»** (Open Anyway) →
   подтвердите паролем. На macOS Sequoia и новее старый способ «правая кнопка →
   Открыть» больше не работает.
3. Альтернатива из терминала — снять карантин:
   `xattr -dr com.apple.quarantine /Applications/LAZEYKA.app`

Hardened runtime и нотаризация выключены (без платного аккаунта разработчика
они невозможны), поэтому файл `build/entitlements.mac.plist` сборкой не
используется.

## Проверка macOS 2.0.0

Workflow «build-mac» на Apple Silicon и Intel проверяет типы, архитектуру сборки,
запускает оба ядра INCY и проверяет запуск и остановку TgWsProxy на локальном
порту. Тестовую сборку можно получить ручным запуском workflow с пустым
полем release_tag.

Проверка приложения на Mac перед релизом:

1. Установить DMG, пройти первый запуск, открыть «Что нового», повторно
   запустить экскурсию и проверить восстановление размера окна.
2. Проверить INCY в режиме прокси и TUN. Подключить рабочий узел, собрать
   цепочку с двумя рабочими узлами, затем проверить отказ с недоступным
   входом. После отключения должны вернуться обычные маршруты и DNS.
3. Включить и выключить службу Zapret, проверить отдельную стратегию,
   затем убедиться, что приложение возвращает прежнюю стратегию.
4. Проверить Telegram Desktop через локальный прокси, DNS-профиль в
   «Системных настройках» и его сброс. В «Диагностике» проверить сайт с
   рабочим адресом и с ошибкой.
5. Подключиться к пульту с телефона по QR и проверить прокси из той же сети.
   Проверить фон, настройки, поддержку и уведомления. Заявки поддержки
   проверять с тестовым Hub.

## Сборка Ubuntu

GitHub Actions запускает `build-linux` на Ubuntu 24.04 x64 после публикации
релиза. Процесс запускает `pnpm build:linux`, проверяет архитектуру и запуск
ядер, публикует артефакт и добавляет пакет к релизу. Уже загруженный пакет
остаётся в релизе, поэтому опубликованная контрольная сумма не меняется.

Тестовую сборку можно запустить из Windows командой
`gh workflow run build-linux.yml --ref main`. Для сборки под существующий
релиз передайте `-f release_tag=v<версия>`. Готовый файл называется
`LAZEYKA_amd64.deb`. Команда установки есть в разделе [Ubuntu](./README.md#ubuntu).

В разделе Zapret доступны 22 стратегии Flowseal 1.10.3, адаптированные
для нативного nfqws. При сборке каждый профиль проверяется командой
`nfqws --dry-run`. Можно проверить одну стратегию, весь каталог или
сразу выбрать стратегию с лучшим результатом. При равном результате
сохраняется текущая стратегия. Каталог использует штатные списки Flowseal.
Движок работает как системная служба и обрабатывает исходящий трафик
компьютера через nftables. Для кнопки питания может потребоваться
подтверждение администратора. После закрытия приложения служба продолжает
работать. Выключить её можно в LAZEYKA, через пульт или в терминале командой
`sudo systemctl stop lazeyka-zapret.service`.

Поддерживаются TUN и фильтрация по приложениям ExitLag. При запуске TUN
Linux запрашивает права администратора. Маршруты и интерфейс удаляются при
отключении и завершении ядра. «Системный прокси» доступен в сеансе GNOME
и возвращает прежние пользовательские настройки после отключения.

Системный DNS в Ubuntu работает через systemd-resolved. LAZEYKA проверяет
выбранный DNS перед его включением. «Восстановить DNS» возвращает настройки
операционной системы. Для изменения DNS при активном TUN сначала отключите
туннель.

В Zapret можно задавать домены и исключения, выбирать IPset и порты
Game Filter. Конструктор создаёт вариант встроенной стратегии с выбранным
числом повторов пакетов.

Обновления, включая версию nfqws, ставятся из нового deb.
